# گام ۵ — راهنمای اجرا، اعتبارسنجی و محدودیت‌ها

این سند فهرست کارهایی را که برای اطمینان از صحت محلی‌سازی فارسی باید روی
ماشین توسعه اجرا شوند، به‌همراه نتایج مورد انتظار و محدودیت‌های شناخته‌شده
مستند می‌کند.

## ۱) پیش‌نیازها

- دات‌نت **۱۰** (مطابق `global.json` ریشهٔ مخزن).
- CLI ابزار Aspire (برای `aspire run`) یا Visual Studio 2022 با پشتیبانی Aspire.
- Docker Desktop (یا Podman) برای اجرای Redis/Postgres/سایر منابع.
- Node.js + npm فقط برای آزمون‌های سرتاسری (Playwright).

## ۲) اجرای برنامه

```console
git clone https://github.com/smam6/eshop-persian.git
cd eshop-persian
dotnet restore
aspire run
```

پس از بالا آمدن داشبورد، برنامهٔ `webapp` را باز کنید. رابط به‌صورت پیش‌فرض
فارسی و راست‌به‌چپ است؛ تاریخ‌ها شمسی و قیمت‌ها با واحد تومان و ارقام فارسی
نمایش داده می‌شوند.

### تغییر فرهنگ بین فارسی/انگلیسی

- پیش‌فرض سرور `fa-IR` است (بخش `Localization` در `LocalizationExtensions.cs`).
- با `?culture=en-US` در URL می‌توان همهٔ متن‌های resx را به انگلیسی برگرداند؛
  انتخاب در کوکی `.AspNetCore.Culture` ذخیره می‌شود.
- تنظیمات نمایش در بخش `Persian` فایل `src/WebApp/appsettings.json`:

| کلید | مقدار پیش‌فرض | کارکرد |
|---|---|---|
| `UsePersianDigits` | `true` | ارقام فارسی در قیمت/تعداد/تاریخ |
| `CurrencySymbol` | `تومان` | واحد پول |
| `CurrencyDecimals` | `0` | رقم اعشار قیمت |
| `ShowCurrencySymbol` | `true` | نمایش واحد پول |

### کاربران نمونه

`alice` و `bob` با گذرواژهٔ `Pass123$`؛ نشانی نمونهٔ آن‌ها در `UsersSeed.cs`
به تهران تغییر یافته تا صفحهٔ تسویه حساب فارسی پر شود.

## ۳) آزمون‌ها

```console
:: واحد + کارکردی (برای functional‌ها Docker لازم است)
dotnet test tests/Application.UnitTests/Application.UnitTests.csproj
dotnet test tests/Catalog.FunctionalTests/Catalog.FunctionalTests.csproj
dotnet test tests/ClientApp.UnitTests/ClientApp.UnitTests.sln
dotnet test tests/Ordering.UnitTests/Ordering.UnitTests.csproj
dotnet test tests/Basket.UnitTests/Basket.UnitTests.csproj

:: سرتاسری (نصب یک‌باره: npm ci && npx playwright install chromium)
npm run test:e2e
```

نتایج مورد انتظار:

- `Application.UnitTests/PersianFormattingTests.cs` — ۱۴ آزمونِ قالب‌بندی
  تاریخ شمسی/ارقام/قیمت: سبز.
- `CatalogApiTests` — آزمون‌های نام دقیق/جزئی/معنایی با دادهٔ فارسی
  («چکمه کوهنوردی واندرر مشکی»، پیشوند «چوب‌دست» با ۴ نتیجه، «پیراهن» با
  ۱ نتیجه) و شمار ۸ دسته/۱۳ برند: سبز.
- `e2e/` — ورود (صفحهٔ فارسی Identity)، افزودن «ساعت مچی جی‌پی‌اس ادونچرر»
  به سبد، افزایش تعداد تا ۴۰٬۰۰۰٬۰۰۰ تومان، تسویه حساب با نشانی تهران و
  شمارش سفارش‌ها: سبز.

## ۴) چک‌لیست بازبینی دستی

1. خانه: تیتر «آمادهٔ یک ماجراجویی جدید هستید؟» راست‌چپ، کارت‌ها با قیمت تومان.
2. صفحهٔ کالا: تصویر سمت راست، دکمهٔ «افزودن به سبد خرید»، برچسب «کالا در سبد خرید».
3. سبد خرید: عنوان «سبد خرید شما»، کم‌وزیاد کردن تعداد با ارقام فارسی، دکمهٔ «تسویه حساب».
4. تسویه حساب: برچسب‌های «نشانی/شهر/استان/کد پستی/کشور» و پیام‌های خطای فارسی.
5. سفارش‌های من: تاریخ‌های شمسی (مثلاً «۱۴۰۴/۰۳/۲۹ — ۱۴:۲۰») و وضعیت‌های فارسی.
6. چت‌بات: برچسب‌های «دستیار خرید» و ورودی راست‌به‌چپ.
7. Identity: صفحهٔ ورود فارسی؛ خطای «نام کاربری یا گذرواژه نامعتبر است.»
8. کلاینت‌های دیگر: HybridApp و WebhookClient فارسی/RTL؛ MAUI با
   `FlowDirection=RightToLeft` و فرهنگ فارسی.

## ۵) محدودیت‌ها

- **کامپایل در محیط توسعهٔ اولیه انجام نشد:** ابزار SDK دات‌نت در دسترس نبود و
  شبکهٔ دسترسی به منابع نصب باز نبود. صحت‌سنجی با ابزار ساختاری انجام شد: پارس resx و
  تقارن ۱۳۰ کلید en/fa، اعتبار و schema فایل `catalog.json`، پارس PostCSS
  همهٔ ۳۴ فایل CSS (گام ۲)، الگوی صفت‌های razor و تعادل تگ‌ها. اجرای
  `dotnet build && dotnet test` روی ماشین توسعه الزامی است.
- بستهٔ NuGet جدید اضافه نشد (net۱۰/Aspire به همهٔ قابلیت‌های لازم مثل
  `Microsoft.Extensions.Localization` ارجاع ضمنی دارد)؛ بنابراین نیازی به
  `dotnet add package` نیست. اگر خطای Missing package گرفتید دقیقاً همان
  ارجاع را به `Directory.Packages.props` اضافه کنید.
- فونت Montserrat/Sans در CSS‌های اصلی باقی مانده و Vazirmatn به‌عنوان
  لایهٔ RTL فارسی (فایل‌های `rtl*.css`) اضافه شده است تا استایل اصلی حفظ شود؛
  در موارد نادر ممکن است ترتیب فونت نیاز به تنظیم دستی داشته باشد.
- کتابخانهٔ Bootstrap پروژه (نسخهٔ LTR از libman.json) تعویض نشده؛ به‌جای آن
  `rtl-fa.css` قواعد جهت‌دار را بازنویسی می‌کند.
- ورودی‌های عددی (تعداد، کد پستی) همچون لатین نگه داشته شده‌اند تا parsing
  مرورگر نشکند؛ ارقام فارسی فقط در لایهٔ نمایش اعمال می‌شوند.
- صفحات اشکال‌زدای Identity (`Diagnostics`، `Grants`) و متن‌های داخلی لاگ‌ها
  عمداً انگلیسی‌اند.
- دادهٔ ماک MAUI (`CatalogMockService` و…) فقط در حالت ماک نمایش داده می‌شود؛
  در اتصال به API واقعی، همان کاتالوگ فارسی `catalog.json` دیده می‌شود.
- وضعیت سفارش در API همچون انگلیسی ذخیره می‌شود (`SUBMITTED` و…) و فقط در
  نمایش به فارسی ترجمه می‌شود (نگاشت در `Orders.razor`).
