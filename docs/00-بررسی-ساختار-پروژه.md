# گام ۰: بررسی ساختار پروژه eShop و برنامهٔ فارسی‌سازی

> این سند بخش «آماده‌سازی و مرور ساختار پروژه» از طرح شش‌مرحله‌ای فارسی‌سازی فروشگاه مرجع مایکروسافت eShop است.  
> هدف آن مستندسازی دقیق ساختار فعلی راهکار، تفکیک پروژه‌های رابط کاربری از پروژه‌های صرفاً API و تعیین نقاط تماس برای اعمال محلی‌سازی (Localization)، راست‌به‌چپ (RTL) و جهانی‌سازی (Globalization) است.

---

## ۱. دورنمای راهکار

پروژهٔ **eShop (AdventureWorks)** یک نمونهٔ مرجع مبتنی بر **.NET 10 + ‎.NET Aspire** است که با معماری سرویس‌گرا پیاده‌سازی شده. فایل‌های راهکار (Solution) در ریشه قرار دارند:

| فایل راهکار | کاربرد |
|---|---|
| `eShop.slnx` | راهکار اصلی – همهٔ سرویس‌ها، کلاینت‌ها و تست‌ها |
| `eShop.Web.slnf` | فیلتر سبک‌تر برای اجرای محلی Web + APIها بدون MAUI |

`global.json` نسخهٔ SDK مورد نیاز را `10.0.302` با `rollForward: latestFeature` تعیین می‌کند.

## ۳. تشخیص پروژه‌های دارای رابط کاربری (UI)

| پروژه UI | فناوری UI | زبان واسط | نیاز به RTL | نیاز به ترجمه |
|---|---|---|---|---|
| **WebApp** | Blazor Server (Razor Components) با `App.razor` + `MainLayout.razor` + صفحات `Catalog/Cart/Checkout/Item/User` | HTML/CSS/JS + Razor | **بله – اولویت ۱** | **بله** |
| **WebAppComponents** | Razor Class Library – `CatalogListItem.razor`, `CatalogSearch.razor` | Razor + CSS | بله – کامپوننت‌های مشترک | بله |
| **HybridApp** | MAUI Blazor Hybrid (`MauiProgram.cs`, `MainPage.xaml`) | XAML + Blazor | بله (در فاز بعدی) | بله |
| **ClientApp** | MAUI خالص (XAML MVVM) | XAML | بله (در فاز بعدی) | بله |

> **تصمیم طراحی:** در این نمونه، فارسی‌سازی کامل روی **WebApp + WebAppComponents** متمرکز می‌شود (قابل نمایش در مرورگر بدون نیاز به MAUI workload). پروژه‌های MAUI نیز آمادهٔ اعمال همان الگو (RESX + FlowDirection) هستند و اسکلت فارسی‌سازی برای آن‌ها نیز تعبیه می‌شود.

پروژه‌های API-محور (`Basket.API`, `Catalog.API`, `Identity.API`, `Ordering.API`, `Webhooks.API`) رابط کاربری ندارند؛ تنها **پیام‌های خطا و اعتبارسنجی کاربر-محور** آن‌ها نیاز به محلی‌سازی دارد (مثلاً `CatalogDomainException`, `ModelState` در Ordering).

## ۴. نقاط کلیدی برای محلی‌سازی

### WebApp – هستهٔ فارسی‌سازی
- `Program.cs`: محل تزریق `AddLocalization`, `RequestLocalizationOptions` با فرهنگ `fa-IR`
- `Extensions/Extensions.cs`: `AddApplicationServices()` – مکان مناسب برای توسعهٔ `AddPersianLocalization()`
- `Components/App.razor`: تگ `<html>` – افزودن `lang="fa" dir="rtl"`
- `Components/Layout/MainLayout.razor` + `HeaderBar/FooterBar/UserMenu/CartMenu` – چیدمان RTL و ترجمهٔ برچسب‌ها
- `Components/Pages/**` – تمام عناوین، دکمه‌ها، پیام‌های خالی‌بودن سبد، صفحه‌بندی، اعتبارسنجی فرم تسویه
- `wwwroot/css/app.css` + `wwwroot/css/rtl.css` (جدید) – وارونه‌سازی margin/padding و فونت فارسی (Vazirmatn)
- `wwwroot/js/*` – بررسی `catalog-sort.js`, `chat-*.js` برای سازگاری RTL
- `Services/BasketCheckoutInfo.cs` – افزودن `ErrorMessage` فارسی به DataAnnotations
- `Services/PriceFormatter.cs` (در WebAppComponents) – تغییر از `InvariantCulture` + `$` به `fa-IR` + `تومان`

### Catalog.API – داده‌های نمونه
- `Setup/catalog.json` (۱۰۲ قلم): نام، برند، نوع، توصیف، قیمت – ترجمه به فارسی رسمی
- `Infrastructure/CatalogContextSeed.cs`: بدون تغییر منطقی، فقط داده‌های ورودی فارسی می‌شوند

### Identity / Ordering / Basket
- پیام‌های `IdentityModel` و `Ordering.Domain` در صورت نمایش به کاربر، به پروندهٔ منابع منتقل می‌شوند.

## ۵. استراتژی نگارش فارسی

- لحن رسمی فروشگاهی: «سبد خرید»، «تسویه حساب»، «افزودن به سبد خرید»، «سفارش‌های من»، «ورود»، «خروج»
- حفظ نام برند انگلیسی (AdventureWorks) در جایگاه لوگو، اما ترجمهٔ شعارها
- واحد پول: **تومان** (نماد: `تومان`، جداکنندهٔ هزارگان فارسی)
- تقویم: نمایش با **تقویم هجری شمسی (PersianCalendar)**، ذخیره در دیتابیس هم‌چنان میلادی (UTC)

## ۶. پیش‌نیازهای اجرا (یادآور)

- ‎.NET SDK 10.0.3xx
- Aspire CLI (`aspire --version`)
- Docker Desktop / Podman فعال
- پورت‌های پیش‌فرض آزاد (Postgres, Redis, RabbitMQ, Aspire Dashboard)

دستور اجرا پس از فارسی‌سازی بدون تغییر می‌ماند:

```bash
aspire run
# یا
dotnet run --project src/eShop.AppHost/eShop.AppHost.csproj
```

داشبورد Aspire پس از بالا آمدن، آدرس‌های `webapp`, `catalog-api`, `basket-api` و … را نمایش می‌دهد.
