# گام ۲ — چیدمان راست‌به‌چپ (RTL)

در این گام، جهت سند، سبک‌های جهتی و تایپوگرافی فارسی در هر سه کلاینت وب
(و کلاینت موبایل) اصلاح شد.

## ۱) تگ `<html>` در همهٔ کلاینت‌ها

| کلاینت | فایل | تغییر |
| --- | --- | --- |
| Blazor WebApp | `src/WebApp/Components/App.razor` | `<html lang="fa" dir="rtl">` + افزودن `css/rtl.css` بعد از `WebApp.styles.css` |
| Blazor HybridApp (MAUI BlazorWebView) | `src/HybridApp/wwwroot/index.html` | `<html lang="fa" dir="rtl">`، `dir="rtl"` روی ریشهٔ `#app` + افزودن `css/rtl.css` |
| WebhookClient | `src/WebhookClient/Components/App.razor` | `<html lang="fa" dir="rtl">` + افزودن `rtl.css` |
| Identity (MVC + Razor) | `src/Identity.API/Views/Shared/_Layout.cshtml` | `<html lang="fa" dir="rtl">` + افزودن `css/rtl-fa.css` بعد از `bootstrap.min.css` و `site.css` |
| MAUI native (ClientApp) | `src/ClientApp/AppShell.xaml` | `FlowDirection="RightToLeft"` روی ریشهٔ `Shell` |

> رویهٔ `rtl.css` عمداً **آخر از همه** لینک می‌شود تا استایل‌های scoped
> کامپوننت‌ها (`WebApp.styles.css`) قابل بازنویسی باشند. برای همین در
> `rtl.css` همهٔ قواعد با پیشوند `html[dir="rtl"]` نوشته شده‌اند تا
> specificity بالاتری نسبت به `.selector[b-…]` داشته باشند.

همچنین ریشهٔ محتوا هم صریحاً RTL شده است (`<main dir="rtl">` در
`MainLayout.razor` هر دو کلاینت) تا محتوایی که ممکن است بیرون از قالب رندر
شود، جهتش را از دست ندهد.

## ۲) تبدیل ویژگی‌های فیزیکی به منطقی (منطق اصلی کار)

به‌جای نوشتن فایل «قرینه‌ساز» که همه‌چیز را با `!important` بازنویسی کند،
ویژگی‌های جهت‌دار در CSS خودِ کامپوننت‌ها به **ویژگی‌های منطقی** تبدیل شدند؛
با این کار چیدمان به‌طور ذاتی با تغییر `dir` قرینه می‌شود و نسخهٔ انگلیسی
(`?culture=en-US`) هم خراب نمی‌شود:

| قبل (فیزیکی) | بعد (منطقی) | فایل‌ها |
| --- | --- | --- |
| `margin-left: auto` | `margin-inline-start: auto` | `HeaderBar`, `CartPage`, `Chatbot`, `CatalogListItem`, `Catalog.razor.css` (Hybrid), `WebhookClient/MainLayout` |
| `margin-right: auto` | `margin-inline-end: auto` | `Chatbot`, `HybridApp/HeaderBar`, `HybridApp/FooterBar`, `Identity/site.css` |
| `padding-left: .35rem` | `padding-inline-start: .35rem` | `Chatbot`, `WebhookClient/app.css` |
| `left: 0` / `right: 0` | `inset-inline-start/-end` | `MainLayout` (خطای Blazor)، `UserMenu`، `Catalog.razor.css` (لیست مرتب‌سازی)، `ItemPage` (بَج زوم، دکمهٔ بستن)، `CatalogListItem` (چیپ برند)، `HybridApp/HeaderBar` |
| `text-align: left` / `right` | `text-align: start` / `end` | `UserMenu`, `CatalogListItem`, `Orders` |
| `border-bottom-left/right-radius` | `border-end-start/end-end-radius` | `Chatbot` (دمِ حباب گفت‌وگو) |

مواردی که **عمداً فیزیکی ماندند** (چون مکان فیزیکی دارند و نباید قرینه شوند):
دستگیره‌های تغییر اندازهٔ پنجرهٔ دستیار (`chatbot-grip-*`) و دکمهٔ شناورِ
دستیار که با `chat-fab.js`/`chat-dock.js` جای‌گذاری می‌شوند؛ آن اسکریپت‌ها
با مختصات viewport کار می‌کنند و مستقل از جهت متن‌اند.

## ۳) فونت فارسی

`Vazirmatn` (نسخهٔ ۳۳.۰.۳، پروانهٔ SIL OFL 1.1) به‌صورت **خودی Host** در هر
کلاینت افزوده شد تا پروژه به CDN وابسته نباشد:

```
src/WebApp/wwwroot/fonts/vazirmatn/        (Regular 400, Medium 500, SemiBold 600, Bold 700 + OFL.txt)
src/HybridApp/wwwroot/fonts/vazirmatn/
src/WebhookClient/wwwroot/fonts/vazirmatn/
src/Identity.API/wwwroot/fonts/vazirmatn/
```

ترتیب خانوادهٔ فونت:

```css
font-family: 'Plus Jakarta Sans', 'Vazirmatn', system-ui, -apple-system, 'Segoe UI', Tahoma, sans-serif;
```

چون فونت برند (Plus Jakarta Sans) گلیف فارسی ندارد، مرورگر **کاراکربه‌کاراک**
سقوط می‌کند: لاتین با فونت برند و فارسی با Vazirmatn رندر می‌شود؛ نتیجه در
متن‌های دوزبانه (نام برندها + متن فارسی) یکدست است.

## ۴) اصلاحات تایپوگرافی فارسی

- `line-height: 1.8` برای بدنه و `1.55` برای تیترها (متن فارسی به نفس بیشتر نیاز دارد).
- بازنشانی `letter-spacing` و `text-transform: uppercase` — فاصله‌گذاری حرفی
  اتصال حروف فارسی را می‌شکند. چون قواعد scoped با `[b-…]` specificity
  `(0,2,1)` دارند، بازنشانی‌ها با مسیر کاملِ کلاس نوشته شده‌اند:
  `.eshop-hero-intro h1`, `.eshop-footer-col h2`, `.catalog-search-group h3`,
  `.catalog-product-brand`, `.cart-items .cart-item-header`, `.orders-header`,
  `.cart-empty h2`, `.orders-empty h2`, `.price`.
- `font-variant-numeric: tabular-nums` روی قیمت/مبلغ/تاریخ تا ستون‌ها نلغزند.
- `unicode-bidi: isolate` و `white-space: nowrap` برای `.price` تا
  «۱٬۲۹۰٬۰۰۰ تومان» در میان متن راست‌به‌چپ نشکند و جابه‌جا نشود.
- فیلدهای ذاتاً لاتین (ایمیل، رمز، تلفن، عدد، تاریخ، URL) `direction: ltr`
  می‌مانند تا مکان‌نما و ترتیب پرانتز/خط‌تیره درست بماند.

## ۵) Bootstrap در Identity

`libman.json` نسخهٔ `bootstrap@5.2.3` (بدون باندل RTL) را می‌آورد؛ پس
`rtl-fa.css` همین چند ابزارِ جهت‌دارِ استفاده‌شده در Views را قرینه می‌کند:
`text-start/end`, `ms-1..5`, `me-1..5`, `ps-*/pe-*`, `float-start/end`,
`border-start/end`, `form-check` (شناور بودن input و حاشیهٔ منفی‌اش)،
`input-group` (شعاع گوشه‌ها)، `alert-dismissible .btn-close` و
`select` (فلش و `background-position`). با این روش نسخهٔ Bootstrap تغییر
نمی‌کند و آپدیت‌پذیری پروژه حفظ می‌شود.

## ۶) راستی‌آزمایی

```bash
# ۱) پارس شدن همهٔ فایل‌های CSS (با postcss):
node -e "
const postcss=require('postcss'),fs=require('fs'),cp=require('child_process');
let bad=0;
for(const f of cp.execSync('find src -name \"*.css\"').toString().trim().split('\n'))
  { try{ postcss.parse(fs.readFileSync(f,'utf8'),{from:f}); }catch(e){ bad++; console.log('FAIL',f,e.message.split('\n')[0]); } }
console.log('css failures:',bad);"

# ۲) هیچ ویژگی فیزیکی جهت‌دار در CSS کلاینت‌ها نمانده باشد:
grep -rn "margin-left\|margin-right\|padding-left\|padding-right\|text-align: left\|text-align: right" \
  src/WebApp src/WebAppComponents src/HybridApp src/WebhookClient --include=*.css
```

خروجی این `grep` در `src/WebApp`، `src/WebAppComponents`، `src/HybridApp`
و `src/WebhookClient` تهی است (قرینه‌سازی کامل). در `rtl-fa.css` و
`site.css` هم بازنویسی‌ها با `html[dir="rtl"]` شرطی شده‌اند، پس حالت LTR
دست‌نخورده می‌ماند.

بررسی چشمی پس از بالا آمدن برنامه:

```bash
# RTL (پیش‌فرض)
https://localhost:XXXX/            # جهت راست‌به‌چپ، چیپ برند بالا-راست، منوی کاربر به ابتدای ردیف می‌چسبد
# بررسی عدم‌شکست LTR
https://localhost:XXXX/?culture=en-US
```

مواردی که باید در صفحهٔ سبد خرید/تسویه/سفارش‌ها چک شوند: ستون مبلغ در انتهای
ردیف، برچسب تعداد سبد، جهت فلش «بازگشت»، و جدول سرستون‌های سبد.
