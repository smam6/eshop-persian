# گام ۳ — بومی‌سازی تاریخ، عدد و قیمت (Globalization)

## ۱) معماری قالب‌بندی

همهٔ منطق نمایش فارسی در یک پروژهٔ مشترک (**WebAppComponents**) نشسته تا هر سه
کلاینت (Blazor Web، Blazor Hybrid/MAUI و حتی موبایل نیتیو) یک خروجی داشته باشند:

```
src/WebAppComponents/Services/
  PersianCultureHelper.cs       ← ساخت CultureInfo سفارشی fa-IR (تقویم شمسی + تومان)
  PersianDateHelper.cs          ← تبدیل میلادی → شمسی، منطقهٔ زمانی تهران، «دیروز/۲ روز پیش»
  PersianFormat.cs              ← رقم فارسی/لاتین، عدد، قیمت و تاریخ (نقطهٔ واحد نمایش)
  PersianFormattingOptions.cs    ← گزینه‌ها: رقم فارسی، واحد پول، رقم اعشار
  PriceFormatter.cs             ← extension متد ToPriceDisplay() که Razorها صدا می‌زنند
src/ClientApp/PersianGlobalization.cs  ← همان تنظیمات برای کلاینت موبایل نیتیو (MAUI)
```

> در گام ۱ این کلاس‌ها در `src/WebApp/Helpers` بودند؛ در گام ۳ به
> `WebAppComponents` منتقل شدند تا HybridApp هم بدون کپی‌کد از آن‌ها استفاده کند.

## ۲) تزریق فرهنگ سفارشی در `RequestLocalizationOptions`

`src/WebApp/Extensions/LocalizationExtensions.cs`:

```csharp
var persianCulture = PersianCultureHelper.GetPersianCulture(persianOptions);
var englishCulture = PersianCultureHelper.GetEnglishCulture();

options.DefaultRequestCulture = new RequestCulture(persianCulture);
options.SupportedCultures   = [persianCulture, englishCulture];
options.SupportedUICultures = [persianCulture, englishCulture];
```

داخل `GetPersianCulture()` هم دقیقاً همان کاری انجام می‌شود که در خواسته آمده بود:

```csharp
var culture = new CultureInfo("fa-IR");
culture.DateTimeFormat.Calendar = new PersianCalendar();
culture.DateTimeFormat.ShortDatePattern = "yyyy/MM/dd";
culture.DateTimeFormat.MonthNames = ["فروردین", … , "اسفند", ""];
culture.DateTimeFormat.FirstDayOfWeek = DayOfWeek.Saturday;
culture.NumberFormat.NumberDecimalSeparator = "٫";   // U+066B
culture.NumberFormat.NumberGroupSeparator  = "٬";    // U+066C
culture.NumberFormat.CurrencySymbol = "تومان";
culture.NumberFormat.CurrencyPositivePattern = 3;    // n L → «۱٬۲۳۰ تومان»
```

نتیجه: هر `DateTime.ToString()` و `decimal.ToString("C")` در سراسر برنامه
(بدون تغییر کد) شمسی و فارسی می‌شود. برای پایداری رفتار روی همهٔ سکو‌ها،
ارقام در سطح فرهنگ **لاتین** نگه داشته شده و تبدیل رقم به فارسی در لایهٔ
نمایش انجام می‌شود (`PersianFormat.ToPersianDigits`); به این ترتیب
`input[type=number]` و `decimal.Parse` در فرم‌ها نمی‌شکنند.

اگر محیط در حالت `Globalization-Invariant` باشد یا `fa-IR` در دسترس نباشد،
`TryCreateCulture` به اینواریانت برمی‌گردد و برنامه بالا می‌آید (فقط شکل
ارقام/جداکننده‌های پیش‌فرض فرهنگ استفاده نمی‌شود؛ جداکننده‌ها را خودمان ست می‌کنیم).

## ۳) قیمت

`PriceFormatter` پیش‌تر فقط `1,234.50` (اینواریانت) می‌داد و `$` درون
`.razor` hard-code شده بود. اکنون:

```csharp
public static string ToPriceDisplay(this decimal value)
    => value.ToPriceDisplay(CultureInfo.CurrentCulture);

public static string ToPriceDisplay(this decimal value, CultureInfo culture)
    => PersianFormat.FormatCurrency(value, culture);
```

خروجی:

| فرهنگ | خروجی |
| --- | --- |
| fa-IR | `۱٬۲۹۰٬۰۰۰ تومان` (بدون اعشار، ارقام فارسی) |
| en-US (fallback) | `$1,290.00` (رفتار قبلی eShop) |

نماد پول دیگر در Markup تکرار نمی‌شود؛ همهٔ فراخوانی‌ها از حالت
`$@item.Price.ToPriceDisplay()` به `@item.Price.ToPriceDisplay()` تغییر کردند
(۷ نقطه: `CatalogListItem`, `CartPage` ×۳, `ItemPage` ×۲, `Orders`,
`HybridApp/ItemPage`). واحد پول و رقم اعشار از پیکربندی خوانده می‌شود:

```json
// src/WebApp/appsettings.json
"Persian": {
  "UsePersianDigits": true,
  "CurrencySymbol": "تومان",
  "CurrencyDecimals": 0,
  "ShowCurrencySymbol": true
}
```

برای «ریال» فقط `"CurrencySymbol": "ریال"` کافی است — کد رابط کاربری تغییر نمی‌کند.

## ۴) تاریخ

- `PersianDateHelper` تاریخ را با `PersianCalendar` و پس از بردن به منطقهٔ زمانی
  `Asia/Tehran` (و در ویندوز `Iran Standard Time`) تبدیل می‌کند؛ اگر منطقهٔ زمانی
  پیدا نشود، بدون خطا ادامه می‌دهیم.
- `PersianFormat.FormatDate(order.Date)` در صفحهٔ سفارش‌ها: `۱۴۰۴/۰۷/۲۶`
  و برچسب نسبی `دیروز` / `۳ روز پیش`.
- `DateTime.Now.Year` در پابرگ به `© ۱۴۰۵` (سال شمسی) تبدیل شد و در حالت
  انگلیسی همان `© 2026` می‌ماند.
- شمارندهٔ سبد خرید (`99+`) هم رقم فارسی می‌گیرد.
- **مهم:** دادهٔ ماندگار تغییر نمی‌کند. `ParseExpiryDate` در `Checkout.razor`
  که پیش‌تر `null` (یعنی CurrentCulture) می‌گرفت، به
  `CultureInfo.InvariantCulture` تغییر کرد؛ اگر فرهنگ فارسی با تقویم شمسی به
  تجزیهٔ «۱۴۰۳/۰۵/۲۴» اعمال می‌شد، سال اشتباه در دیتابیس ذخیره می‌شد.
  رقم فارسی ورودی کاربر هم پیش از تجزیه با `PersianFormat.ToLatinDigits`
  نرمال می‌شود.
- `data-sort-price` در کارت محصول عملاً `CultureInfo.InvariantCulture` می‌ماند،
  چون اسکریپت مرتب‌سازی همان عدد را دوباره `parseFloat` می‌کند.
  `catalog-sort.js` برای هم‌سنجی نام‌ها از `document.documentElement.lang`
  استفاده می‌کند تا ترتیب حروف فارسی درست باشد.

## ۵) کلاینت موبایل

- `HybridApp/MauiProgram.cs`: تنظیم `CultureInfo.DefaultThreadCurrentCulture` و
  `DefaultThreadCurrentUICulture` روی فرهنگ فارسی + `PersianFormat.Configure`.
- `ClientApp` (MAUI نیتیو، بدون ارجاع به WebAppComponents):
  `src/ClientApp/PersianGlobalization.cs` همین فرهنگ را می‌سازد و در ابتدای
  `CreateMauiApp()` اعمال می‌شود. در XAML هم همهٔ
  `StringFormat='${0:N2}'` / `'{0:C2}'` به `StringFormat='{0:C}'` تبدیل شد تا
  نماد پول از فرهنگ بیاید (تومان) و `DateTimeFormat` موجود
  (`{0:MMMM dd yyyy}`) خودکار شمسی شود.

## ۷) بسته‌های NuGet

هیچ بستهٔ جدیدی لازم نیست:
`PersianCalendar`، `CultureInfo`، `NumberFormatInfo` و `DateTimeFormatInfo` بخشی از
`System.Globalization` روی .NET 10 هستند و
`Microsoft.Extensions.Localization` / `Microsoft.AspNetCore.Localization` هم در
فریم‌ورک مشترک `Microsoft.AspNetCore.App` آمده‌اند. به همین دلیل در `*.csproj`
ها فقط یک `ProjectReference` (برای پروژهٔ تست) افزوده شد و هیچ
`PackageReference` تازه‌ای نیاز نشد.

> اگر روزی بخواهید تقویم/رقم را با بستهٔ شخص ثالث بسازید، دستور آماده است؛
> ولی در این نمونه عمداً از کتابخانهٔ استاندارد استفاده شده تا وابستگی و
> هزینهٔ نگهداری اضافه نشود:
> `dotnet add src/WebAppComponents package <package-name>`
